# 🎯 Strategy Optimization Workflow - MarketMind

## Objective

Systematically improve the performance of all strategies through parameter optimization, focusing on increasing the **Profit Factor** from 1.13-1.36 to 1.5-2.5 (industry benchmark).

## Identified Problem

After comparative analysis against benchmarks:
- ✅ Win Rates are correct (28-67% depending on strategy type)
- ❌ Profit Factors are low (1.13-1.36 vs expected 1.5-2.5)
- ❌ PnL is low/negative (-3.75% to +0.93%)

**Root cause:** R:R (Risk:Reward) parameters, targets, and stops are not optimized.

## Optimization Strategy

### 1️⃣ Phase 1: Full Optimization (3 Stages)

**Run:**
```bash
cd apps/backend
pnpm optimize:full
```

**What it does:**
- Stage 1: Sensitivity sweep (Fibonacci targets, entry progress, R:R ratios)
- Stage 2: Cross-product of the top Stage 1 combinations
- Stage 3: Trailing stop optimization on the best configs
- Supports SIGINT/SIGTERM (saves progress for resume)
- ETA display, kline gap warnings, per-symbol stats

**Output:** `/tmp/prod-parity-optimization-run/` (summary.txt, optimal-config.json, CSVs)

### 2️⃣ Phase 2: Apply Optimized Parameters

**Run:**
```bash
pnpm tsx scripts/audit/apply-optimizations.ts
```

**What it does:**
- Reads the `optimal-config.json` generated by Stage 2
- Applies the best parameters to the production configuration
- Maintains a history of previous optimizations

### 3️⃣ Phase 3: Validate Results

**Run:**
```bash
pnpm backtest:validate -- \
  --strategy order-block-fvg \
  --symbol BTCUSDT \
  --interval 1h \
  --start 2024-06-01 \
  --end 2024-12-31
```

**What to validate:**
- ✅ Profit Factor > 1.5 (minimum target)
- ✅ Positive PnL in the test period
- ✅ Win Rate maintained or improved
- ✅ Max Drawdown under control (<10%)

### 4️⃣ Phase 4: Walk-Forward Analysis (Robustness)

**Run:**
```bash
npm run backtest:walkforward -- \
  --strategy order-block-fvg \
  --symbol BTCUSDT \
  --interval 1h \
  --start 2023-01-01 \
  --end 2024-12-31 \
  --training-months 6 \
  --testing-months 2 \
  --step-months 2
```

**What to evaluate:**
- Performance degradation < 30% (in-sample vs out-of-sample)
- Consistency across testing periods
- Overall robustness (ROBUST or NOT ROBUST)

## Optimized Parameters by Strategy Type

### Smart Money (Order Blocks, Liquidity Sweeps)
- `lookbackPeriod`: 30-60 candles
- `orderBlockVolumeMultiplier`: 1.2-1.8x
- `targetMultiplier`: 1.5-3.0 (focus on increasing R:R)

### Momentum/Trend (Larry Williams, Divergences)
- `lookbackDays`: 3-7 days
- `rsiPeriod`: 10-16
- `divergenceLookback`: 10-20
- `targetMultiplier`: 2.0-3.5 (increase targets)

### Mean Reversion (Connors RSI2, BB-RSI)
**MAIN FOCUS:** Increase targets and reduce stops to improve R:R
- `rsiOversoldLevel`: 5-15
- `targetPercent`: 0.5-2.0% (INCREASE - was too low)
- `stopLossPercent`: 1.5-2.5% (REDUCE - was too wide)
- `bbStdDev`: 1.5-2.5

## Troubleshooting

### Optimization is too slow
- Reduce `--parallel` from 4 to 2
- Reduce the parameter grid (fewer values)
- Use a shorter period (6 months instead of 2 years)

### No configuration passes the filters
- Reduce `--min-win-rate` from 30% to 25%
- Reduce `--min-profit-factor` from 1.3 to 1.2
- Widen the parameter grid

### Performance is worse after optimization
- Overfitting! Use walk-forward analysis
- Widen the parameter grid (less granular)
- Increase the optimization period
